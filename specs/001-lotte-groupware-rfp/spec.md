## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 통합 로그인 및 개인화 포탈 접근 (Priority: P1)

일반 사용자는 한 번의 로그인으로 그룹웨어에 접속하고, 자신의 업무에 최적화된 맞춤형 포탈 화면을 통해 필요한 정보와 기능에 빠르게 접근할 수 있다.

**우선순위 이유**: 시스템의 첫인상이자 모든 업무의 시작점입니다. 싱글사인온(SSO)과 개인화 포탈은 사용자의 편의성을 극대화하고 정보 접근성을 높이는 가장 핵심적인 기능입니다.

**독립적 테스트**: 사용자가 로그인 자격증명(ID/PW, 생체인증 등)을 사용하여 성공적으로 로그인하고, 사전에 설정된 개인화 포틀릿이 포함된 메인 화면을 볼 수 있는지 확인합니다. 포틀릿을 직접 편집(추가/삭제/이동)하고 저장할 수 있는지 검증합니다.

**수용 시나리오**:

1.  **Given** 사용자가 로그인 페이지에 접근했을 때, **When** ID와 패스워드를 입력하고 로그인 버튼을 클릭하면, **Then** 시스템은 사용자 인증을 성공시키고 개인화된 포탈 메인 화면으로 리디렉션한다.
2.  **Given** 사용자가 로그인한 상태에서, **When** 포탈 화면의 '편집' 기능을 사용하여 포틀릿을 Drag & Drop으로 이동시키면, **Then** 포틀릿의 위치가 변경되고 해당 레이아웃이 사용자에게 저장된다.
3.  **Given** 사용자가 모바일 기기에서 그룹웨어에 접근할 때, **When** 생체 인증(지문/Face ID)을 시도하면, **Then** 시스템은 2-Factor 인증을 통해 안전하게 로그인시키고 모바일용 포탈 화면을 보여준다.

### 사용자 스토리 2 - 전자결재 문서 기안 및 처리 (Priority: P1)

팀원은 휴가 신청서 양식을 사용하여 결재 문서를 기안하고, 지정된 결재선(팀장, 부서장)에 따라 문서를 상신한다. 결재자는 푸시 알림을 받고 모바일에서 내용을 검토한 후 승인 또는 반려 처리를 할 수 있다.

**우선순위 이유**: 전자결재는 기업의 핵심 업무 프로세스를 자동화하고 의사결정 속도를 높이는 필수 기능입니다. 수기 업무를 온라인화하여 업무 효율을 증대시키고 이력을 자산화합니다.

**독립적 테스트**: 사용자가 결재 양식을 선택하여 내용을 작성하고 결재선을 지정하여 상신할 수 있는지 확인합니다. 결재자가 해당 문서를 조회하고 승인/반려 처리를 할 수 있는지, 그리고 그 결과가 기안자에게 정상적으로 통보되는지 검증합니다.

**수용 시나리오**:

1.  **Given** 기안자가 결재 메뉴에서 '기안하기'를 선택했을 때, **When** '휴가신청서' 양식을 검색하여 선택하고, 휴가 기간과 사유를 입력한 후, 조직도에서 팀장과 부서장을 결재자로 지정하여 '상신' 버튼을 누르면, **Then** 결재 문서가 생성되고 첫 번째 결재자(팀장)에게 결재 요청 알림이 발송된다.
2.  **Given** 결재자가 모바일에서 결재 요청 Push 알림을 받았을 때, **When** 알림을 탭하여 결재 문서를 열고 '승인' 버튼을 누르면, **Then** 해당 결재 단계가 완료되고 다음 결재자에게 알림이 가거나 모든 결재가 완료된다.
3.  **Given** 최종 결재자가 결재를 완료했을 때, **When** 시스템이 결재 종결 처리를 하면, **Then** 기안자에게 '결재 완료' 알림이 발송되고 해당 문서는 결재 완료 문서함에 보관된다.

### 사용자 스토리 3 - 협업을 위한 게시판 활용 (Priority: P2)

부서 관리자는 부서원 전체에게 공지할 내용이 있어, 부서 게시판에 중요 공지사항을 게시한다. 게시물에는 관련 파일이 첨부되며, 등록 시 부서원들에게 알림이 발송된다. 부서원은 게시물을 읽고 댓글로 의견을 남길 수 있다.

**우선순위 이유**: 게시판은 사내 정보 공유를 활성화하고, 부서 및 팀 단위의 협업 기반을 마련하는 중요한 소통 도구입니다.

**독립적 테스트**: 사용자가 특정 게시판에 제목과 내용을 작성하고 파일을 첨부하여 게시물을 등록할 수 있는지 확인합니다. 다른 사용자가 이 게시물을 조회하고 댓글을 작성할 수 있는지 검증합니다.

**수용 시나리오**:

1.  **Given** 사용자가 '부서 게시판'에 접근했을 때, **When** '글쓰기' 버튼을 눌러 제목과 내용을 입력하고, '파일 첨부' 기능을 이용해 문서를 첨부한 후 '등록' 버튼을 클릭하면, **Then** 새로운 게시물이 게시판 목록에 나타나고 부서원들에게 알림이 발송된다.
2.  **Given** 다른 사용자가 게시판 목록에서 새로운 글을 확인했을 때, **When** 글 제목을 클릭하여 내용을 읽고, 하단의 댓글 입력창에 의견을 작성한 후 '댓글 등록' 버튼을 누르면, **Then** 해당 게시물 하단에 댓글이 추가되고 원작성자에게 댓글 알림이 간다.

### 엣지 케이스

-   대용량 파일(예: 1GB 이상) 첨부 시 시스템은 어떻게 반응하는가? (일반/대용량 첨부 전환)
-   결재 진행 중 결재자가 퇴사하거나 장기 부재 상태가 되면 해당 문서는 어떻게 처리되는가? (대결/후결/관리자 강제 처리)
-   여러 사용자가 동시에 같은 문서를 수정하려고 할 때 충돌은 어떻게 방지하는가?
-   외부망에서 모바일로 접속 시, 네트워크가 불안정하여 연결이 끊겼다가 다시 연결될 때 작업 내용은 유지되는가? (임시저장)

## 요구사항 *(필수)*

### 기능 요구사항

#### 공통 및 기반
- **FR-001**: 시스템은 웹 표준을 준수하며 Chrome, Edge 브라우저에서의 크로스 브라우징을 완벽하게 지원해야 한다.
- **FR-002**: 사용자는 개인화 포탈을 통해 최적화된 업무 환경을 제공받아야 하며, Drag & Drop 방식으로 포틀릿을 직접 구성할 수 있어야 한다.
- **FR-003**: 시스템은 통합 로그인(SSO)을 제공하여 한 번의 인증으로 연동된 모든 시스템을 별도 로그인 없이 이용할 수 있어야 한다.
- **FR-004**: 모바일 등 외부에서 접속 시, 보안 강화를 위해 2-Factor 인증(생체인증, 패턴, PIN 등)을 필수로 거쳐야 한다.
- **FR-005**: 시스템 내에서 발생하는 모든 중요 이벤트(결재, 메일, 게시물 등)는 통합 알림 센터를 통해 사용자에게 실시간으로 전달되어야 한다.
- **FR-006**: 관리자는 IP 대역별 접근 제어, 비밀번호 정책(복잡도, 변경 주기), 비인가 단말기 접속 차단 등 보안 설정을 관리할 수 있어야 한다.
- **FR-007**: 퇴직자 발생 시, 해당 사용자의 권한 및 데이터를 다른 사용자에게 안전하게 인수인계하는 기능이 제공되어야 한다.

#### 핵심 기능 (메일, 결재, 게시판 등)
- **FR-010**: 사용자는 그룹웨어 포탈 내에서 MS Outlook 메일을 연동하여 조회, 작성할 수 있어야 한다. (웹메일 기능 고도화 포함)
- **FR-011**: 메일 작성 시, 대용량 파일 첨부, 보안 메일(비밀번호 설정), 예약 발송, 수신 확인, 발송 회수(읽은 메일 포함) 기능이 제공되어야 한다.
- **FR-012**: 사용자는 Non-ActiveX 기반 웹 에디터를 사용하여 전자결재 문서를 작성하고, 다양한 결재 유형(전결, 대결, 합의, 후결)을 포함한 결재선을 지정할 수 있어야 한다.
- **FR-013**: 결재 진행 중 문서를 수정하거나 결재선을 변경할 수 있어야 하며, 모든 변경 이력은 시스템에 기록되어야 한다.
- **FR-014**: 관리자는 GUI 방식의 Workflow 설정 도구를 사용하여 조직의 결재 프로세스를 손쉽게 생성하고 변경할 수 있어야 한다.
- **FR-015**: 게시판은 일반형, 자료실형, 앨범형 등 다양한 형태로 생성될 수 있어야 하며, 게시물에 대한 댓글 첨부, 익명 설정, 예약 게시 기능을 지원해야 한다.
- **FR-016**: 사용자는 캘린더를 통해 개인, 부서, 전사 일정을 공유하고 조회할 수 있으며, 회의실, 차량 등 공용 자원을 예약할 수 있어야 한다.

#### 확장 기능 (협업, 모바일 등)
- **FR-020**: 사용자는 부서, 팀, 프로젝트 단위의 협업 공간(팀 스페이스)을 개설하여 과제를 관리하고 산출물을 공유할 수 있어야 한다.
- **FR-021**: 시스템은 WBS(작업분류체계) 및 간트 차트 기반의 프로젝트 관리 기능을 제공하여, 프로젝트 진척도를 시각적으로 추적할 수 있어야 한다.
- **FR-022**: 모바일 그룹웨어는 PC와 동일한 수준의 기능을 제공해야 하며(Responsive Layout), 푸시 알림, 모바일 결재, 연락처/일정 동기화를 지원해야 한다.
- **FR-023**: PC와 모바일 양방향으로 동기화되는 업무용 메신저를 제공하며, 대화 내용 검색, 파일 전송, 그룹 대화 기능을 포함해야 한다.
시스템은 Gen AI 연계 기능을 제공해야 하며, 초기 적용 범위는 그룹웨어 내 정보 검색 및 문서 요약 기능을 중심으로 한다.
- **FR-025**: 시스템은 통합 검색 기능을 통해 그룹웨어 내 모든 데이터(결재, 메일, 게시물, 첨부파일)를 한 번에 검색할 수 있어야 한다.

### 주요 엔티티
- **사용자**: 직위, 직책, 부서, 권한 그룹 등의 속성을 가지며 조직도와 연계됨.
- **전자결재 문서**: 양식, 기안자, 결재선, 본문, 첨부파일, 결재 이력 등의 속성을 가짐.
- **게시물**: 게시판, 작성자, 제목, 내용, 첨부파일, 댓글, 조회수, 공지 여부 등의 속성을 가짐.
- **일정**: 소유자, 참석자, 시간, 장소(자원), 반복 설정, 공개 여부 등의 속성을 가짐.
- **자원**: 자원명, 분류, 예약 가능 시간, 관리자, 예약 현황 등의 속성을 가짐.
- **알림**: 수신자, 발신 시스템/기능, 내용, 바로가기 링크, 읽음 상태 등의 속성을 가짐.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 모든 주요 기능(메일, 결재, 게시판 조회)의 화면 평균 응답 시간은 사용자 요청 후 3초 이내여야 한다. (통계 등 5초 이상 소요 시 진행 상태 표시)
- **SC-002**: 시스템은 동시 접속자 1,000명 규모의 부하를 안정적으로 처리해야 하며, 이때 서버 CPU 사용률은 70%를 초과하지 않아야 한다.
- **SC-003**: 신규 그룹웨어 오픈 후 3개월 내, 전자결재 처리 건수가 기존 대비 20% 이상 증가한다.
- **SC-004**: 시스템 장애 발생 시, 이중화된 서버로 5분 이내에 서비스가 자동 복구되어야 한다. (SPOF 제거)
- **SC-005**: 그룹웨어 만족도 설문조사(오픈 6개월 후)에서 '만족' 이상 응답 비율이 80% 이상을 달성한다.
- **SC-006**: 모바일 앱을 통한 업무 처리(결재, 메일 확인) 비율이 전체의 40% 이상을 차지한다.
